## Full-screen Dialog

A Full-screen Dialog presents a series of tasks that must be completed.
It takes over the full screen on mobile and becomes a standard Dialog on
larger screens.

A Dialog can appear above a Full-screen Dialog.

<LinksChipSet
  material="/components/dialogs/guidelines#007536b9-76b1-474a-a152-2f340caaff6f"
  source="/FullscreenDialog.tsx"
/>

```tsx
<FullscreenDialog
  id="edit-profile-dialog"
  title="Edit profile"
  action={
    <Button appearance="filled" command="request-close">
      Save
    </Button>
  }
>
  {/* Content */}
</FullscreenDialog>
```

### Usage

A trigger button can open the Full-screen Dialog via the Invoker Commands API.
Learn more in the [modals and popovers guide](/docs/guides/modals).

```tsx
<Button command="show-modal" commandfor="edit-profile-dialog">
  Edit profile
</Button>
```

Buttons inside the Full-screen Dialog or the `action` prop can close it via
`command="request-close"`, unless a different `commandfor` is specified. “Light
dismiss” is also supported by pressing Escape or clicking the backdrop on larger
screens.

Use `appearance="text"` for the Button in the `action` prop to match the
Material Design spec.

```tsx
// Inside Full-screen Dialog
<Button appearance="text" command="request-close">
  Cancel
</Button>
```

### Props

- [`StyleableProps`](/docs/guides/shared-props): `className` and `style`.

<PropsTable>
  <PropsTableRow prop="children" required="always">
    <TableCell>`ReactNode`</TableCell>
    <TableCell>

      The content.

      - Always required.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="id" required="never">
    <TableCell>`string`</TableCell>
    <TableCell>

      The ID of the `<dialog>` element, for Invoker Commands API support.

      - Use with `command="show-modal"` and `commandfor={id}` on a trigger
        button to open the Full-screen Dialog declaratively via the Invoker
        Commands API.
      - Buttons inside this Dialog will automatically use this ID for their
        `commandfor` when they have a `command` but no explicit `commandfor`.
      - Use `command="request-close"` to close, not `command="close"`.
      - Optional. Defaults to an auto-generated ID.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="open" required="never">
    <TableCell>`boolean`</TableCell>
    <TableCell>

      If the Full-screen Dialog is open and shown.

      - When provided, the Full-screen Dialog is controlled: the consumer must
        call `onClose` on dismiss and set `open` to `false`.
      - When omitted, use `id` together with a trigger button that has
        `command="show-modal"` and `commandfor={id}`.
      - Optional.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="title" required="always">
    <TableCell>`ReactNode`</TableCell>
    <TableCell>

      The title text.

      - Always required.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="action" required="never">
    <TableCell>`ReactNode`</TableCell>
    <TableCell>

      The submission Button.

      - Should be a Button.
      - Optional.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="width" required="never">
    <TableCell>`CSSProperties["width"]`</TableCell>
    <TableCell>

      Full-screen Dialog transforms into a basic Dialog on larger screens. The
      width of the Dialog can be set here.

      - Optional.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="locale" required="never">
    <TableCell>`"en-US" | "th"`</TableCell>
    <TableCell>

      Allows for translation of the accessibility labels.

      - Must be `th` or `en-US`, SKCom supports two languages: th and en-US.
        languages.
      - Optional.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="onClose" required="never">
    <TableCell>`() => void`</TableCell>
    <TableCell>

      The function triggered when the backdrop is clicked or Escape is pressed.

      </TableCell>

  </PropsTableRow>
</PropsTable>
