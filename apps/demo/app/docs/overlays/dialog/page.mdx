## Dialog

A Dialog interrupts the user to make an immediately significant decision
or enter important information.

<LinksChipSet
  material="/components/dialogs/guidelines#97ac3858-3932-4084-ae8e-73e42b7cb752"
  source="/Dialog.tsx"
/>

```tsx
<Dialog id="remove-friend-dialog">
  <DialogHeader
    title="Remove friend?"
    desc="You will not be able to see posts from Akira."
  />
  <Actions>
    <Button appearance="text" command="request-close">
      Cancel
    </Button>
    <Button appearance="text" command="request-close">
      Remove
    </Button>
  </Actions>
</Dialog>
```

### Usage

A trigger button can open the Dialog via the Invoker Commands API. Learn more in
the [modals and popovers guide](/docs/guides/modals).

```tsx
<Button command="show-modal" commandfor="remove-friend-dialog">
  Remove friend
</Button>
```

Buttons inside the Dialog can close it via `command="request-close"`, unless a
different `commandfor` is specified. “Light dismiss” is also supported by
clicking the backdrop or pressing Escape.

Use `appearance="text"` for buttons inside a Dialog to match the Material Design
spec.

```tsx
// Inside Dialog
<Button appearance="text" command="request-close">
  Cancel
</Button>
```

### Props

- [`StyleableProps`](/docs/guides/shared-props) available: `className` and
  `style`.
- [`ElementCustomizableProps`](/docs/guides/shared-props) available: `element`.

<PropsTable>
  <PropsTableRow prop="children" required="always">
    <TableCell>`ReactNode`</TableCell>
    <TableCell>

      Parts of a Dialog.

      - [Dialog Header](/docs/overlays/dialog-header) and [Actions](/docs/inputs/actions) are required components and must appear in the
        said order.
      - If present, [Dialog Content](/docs/overlays/dialog-content) must appear between Dialog Header and Actions.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="id" required="never">
    <TableCell>`string`</TableCell>
    <TableCell>

      The ID of the `<dialog>` element, for Invoker Commands API support.

      - Use with `command="show-modal"` and `commandfor={id}` on a trigger
        button to open the Dialog declaratively via the Invoker Commands API.
      - Buttons inside this Dialog will automatically use this ID for their
        `commandfor` when they have a `command` but no explicit `commandfor`.
      - Use `command="request-close"` to close, not `command="close"`.
      - Optional. Defaults to an auto-generated ID.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="alt" required="conditional">
    <TableCell>`string`</TableCell>
    <TableCell>

      A description of the Dialog for screen readers, similar to `alt` on
      `<img>`.

      - Required if the Dialog does not have a Dialog Header with a title.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="open" required="never">
    <TableCell>`boolean`</TableCell>
    <TableCell>

      If the Dialog is open and shown.

      - When provided, the Dialog is controlled: the consumer must
        call `onClose` on dismiss and set `open` to `false`.
      - When omitted, use `id` together with a trigger button that has
        `command="show-modal"` and `commandfor={id}`.
      - Optional.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="onClose" required="never">
    <TableCell>`() => void`</TableCell>
    <TableCell>

      The function triggered when the backdrop is clicked or Escape is pressed.

      - In controlled mode (`open` is provided), the consumer should set
        `open` to `false` in response.

      </TableCell>

  </PropsTableRow>

  <PropsTableRow prop="width" required="never">
    <TableCell>`CSSProperties["width"]`</TableCell>
    <TableCell>

      The width of the Dialog. This is useful when you want to fit more content
      into a Dialog, or when you have many overlapping Dialogs.

      - Optional.

      </TableCell>

  </PropsTableRow>
</PropsTable>
