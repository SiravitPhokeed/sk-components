## Localization

If your app supports multiple languages, you can pass a `locale` prop to
components that support it. If you don't provide a `locale`, the component
falls back to `en-US`.

SKCom currently supports **`en-US` and `th`.** The following components accept
the `locale` prop:

- [App Drawer](/docs/layout/app-drawer)
- [Button](/docs/inputs/button)
- [Chip Field](/docs/inputs/chip-field)
- [Data Table Head](/docs/data/data-table-head)
- [Data Table Pagination](/docs/data/data-table-pagination)
- [Data Table Search](/docs/data/data-table-search)
- [Full-screen Dialog](/docs/overlays/fullscreen-dialog)
- [Input Chip](/docs/data/input-chip)
- [Nav Bar](/docs/layout/nav-bar)
- [Page Header](/docs/layout/page-header)
- [Search](/docs/inputs/search)
- [Select](/docs/inputs/select)
- [Text Field](/docs/inputs/text-field) (when `type` is `file`)

### Example integrations

SKCom works with any localization library that can give you the current
locale. The general pattern is:

1. Get the current locale from your library's hook or server function.
2. Pass it as the `locale` prop to any SKCom component that supports it.

#### Without a library

If you're using Next.js without a localization library, you can get the
locale from the router or page params.

<DisclosureCard summary="Next.js App Router">

If your routes include a `[locale]` segment, access it from page params.

```tsx
import { NavBar } from "@suankularb-components/react";
import type { FC, ReactNode } from "react";

const RootLayout: FC<{
  children: ReactNode;
  params: { locale: "en-US" | "th" };
}> = ({ children, params }) => {
  const { locale } = params;
  return (
    <html lang={locale}>
      <body>
        <NavBar locale={locale}>{/* ... */}</NavBar>
        {/* ... */}
      </body>
    </html>
  );
};
```

</DisclosureCard>

<DisclosureCard summary="Next.js Pages Router">

Use `useRouter` to access the locale from the router object.

```tsx
import { NavBar } from "@suankularb-components/react";
import { useRouter } from "next/router";
import type { FC } from "react";

const NavBarWithLocale: FC = () => {
  const { locale } = useRouter();
  return <NavBar locale={locale}>{/* ... */}</NavBar>;
};
```

</DisclosureCard>

The table below shows how to get the current locale from popular
internationalization libraries. After the table is a full example showing the
complete pattern.

<Text
  type="body-medium"
  className="text-on-surface-variant *:-mt-2 *:mb-6"
>
  `react-i18next`, `react-intl`, and LinguiJS are hooks-based and require
  wrapping in a Client Component. They still work in App Router — just add
  `"use client"` to any component that calls the hook. `next-i18next` v15
  supports Pages Router only and does not work with App Router.
</Text>

Here is what the full pattern looks like with `next-intl`.

```tsx
// Pages Router / Client Components in App Router
import { NavBar } from "@suankularb-components/react";
import { useLocale } from "next-intl";

const NavBarWithLocale = () => {
  const locale = useLocale();
  return <NavBar locale={locale}>{/* ... */}</NavBar>;
};
```

```tsx
// Async Server Components in App Router
import { NavBar } from "@suankularb-components/react";
import { getLocale } from "next-intl/server";

const NavBarWithLocale = async () => {
  const locale = await getLocale();
  return <NavBar locale={locale}>{/* ... */}</NavBar>;
};
```
