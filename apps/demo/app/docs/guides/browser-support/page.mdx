## Browser support

SK Components is tested against the browsers listed below. Pick the tier that
matches the browser versions you need to support. No polyfills or bundler
configuration is required — modern CSS features are pre-compiled at build time.

<DisclosureCard summary="Case study: real-world traffic to MySK">

To help you decide which tier to support, we analyzed the traffic to a
real-world SK Components site, MySK. The results are as follows:

- **{MYSK_TRAFFIC.full}% of traffic met the <MaterialIcon icon="check_circle" size={20} className="text-primary inline-block -mb-1" />
  full support tier,** held back mainly by older iOS versions (no CSS Anchor
  Positioning or Invoker Commands) and Samsung Internet (no Invoker Commands).

- **{MYSK_TRAFFIC.partial}% of traffic met the <MaterialIcon icon="do_not_disturb_on" size={20} className="text-tertiary inline-block -mb-1 -rotate-45" />

  should support this tier. Consider if your site has similar requirements.

- **{MYSK_TRAFFIC.none}% of traffic <MaterialIcon icon="cancel" size={20} className="text-error inline-block -mb-1" />
  did not meet any tier.** Popovers are not available to these users. It should be
  noted that these users are on browsers that most sites no longer support, and
  they already encounter broken sites across the web.

If you must support these older browsers, note the following:

- [Anchor](/docs/overlays/anchor) is _not supported_ in these browsers. All
  modals and popovers appear in the center of the viewport, and cannot be
  anchored to a trigger element.
- `command` and `commandfor` props are _not supported_ in these browsers. **You
  must use controlled modals and popovers** with the `open` and `onClose` props.

Learn more about [controlled modals and popovers](/docs/guides/modals#controlled-mode).
