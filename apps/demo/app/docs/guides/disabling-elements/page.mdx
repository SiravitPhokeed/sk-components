## Disabling elements

Learn when to make disabled elements in your application less frustrating for
users, and how to implement them in your code.

<Button
  children="Read more"
  appearance="filled"
  disabled
  className="mx-auto my-6"
/>

Elements can be disabled for a variety of reasons, such as when a user does not
have permission to access a feature, or when a feature is temporarily
unavailable.

However, **disabled elements can be frustrating for users if they
do not understand why they are disabled** or how to enable them.

### Less frustrating alternatives

**Remove elements that are unavailable or not applicable** instead of disabling
them. Consider whether the user needs to know about the element at all, and if
they don’t, remove it from the interface.

**Explain why an element is disabled or how to enable it.** If it’s not obvious
why an element is disabled, users may become frustrated and confused. You can
add helper text nearby, or use `helperMsg` in components that support it.

**Never disable form submission buttons, even if the form is invalid.** Instead,
show an error message when the user tries to submit the form.

### `disabled` prop

**To disable an element, use the `disabled` prop.** `ActionableProps` like
`onClick` and `href` will be _ignored_. The element will remain focusable for
accessibility, but will appear visually disabled and will not respond to user
interaction.

<div className="flex md:flex-row flex-wrap gap-4 justify-around items-center my-6">

<AssistChip
  children="See class"
  icon={<MaterialIcon icon="groups" />}
  disabled
/>
<Button children="Create request" appearance="filled" disabled />
<TextField appearance="outlined" label="Full name" disabled className="w-64" />

</div>
