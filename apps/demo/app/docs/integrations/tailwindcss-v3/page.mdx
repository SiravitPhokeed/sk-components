## Using with Tailwind CSS v3

If you are using [Tailwind CSS v3](https://v3.tailwindcss.com), you can
integrate it with SK Components to use utility classes in your project.

<TailwindSelector value="v3" />

### Layers

v3 does not support layers, so you need to use `!important` to override SK
Components styles with Tailwind CSS utility classes.

```tsx
<Button appearance="filled" className="!bg-tertiary !text-on-tertiary">
  Tertiary button
</Button>
```

### Theme

To use the variables provided by [Theme Provider](/docs/layout/theme-provider)
with Tailwind CSS (e.g. `bg-primary`), you need a translation layer between the
two. This is done by pointing to the CSS variables provided by Theme Provider in
your `tailwind.config.ts` file.

The configuration below maps SKCom’s CSS variables to Tailwind’s design tokens.
It covers breakpoints, font weights, font families, font sizes, border radii,

### State layer

Components that use state layers and ripple effects (e.g. Buttons, Chips, etc.)
can have those elements customized with a custom Tailwind CSS plugin.

Import `plugin` from `tailwindcss/plugin` and add the following to your
`tailwind.config.ts` file. This adds `state-layer-*` utility classes.

```ts
import type { Config } from "tailwindcss";
import plugin from "tailwindcss/plugin";

const config: Config = {
  // ...
  plugins: [
    plugin(function ({ matchUtilities, theme }) {
      matchUtilities(
        { "state-layer": (value) => ({ "--state-layer-color": value }) },
        { values: theme("colors") },
      );
    }),
  ],
};
```

The utility classes can then be used like so.

```tsx
<Interactive className="state-layer-primary">
  I have a primary state layer!
</Interactive>
```

### Tailwind CSS v4

Tailwind CSS v4 has built-in layer support, which lets you override SKCom
styles without `!important`. See the [v4 guide](/docs/integrations/tailwindcss-v4)
if you are considering upgrading.
